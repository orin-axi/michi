**Fix applied** (new commit `7a419c4`, not amending d0a25da): added a byte-length guard in `src/toon/render.rs` before calling `truncate_inline` — `s.len() <= max_cell_len` (byte length is always ≥ char count, so this never false-negatives) lets untruncated cells skip straight to `escape_value(s)`, restoring the zero-allocation path for the common case.
