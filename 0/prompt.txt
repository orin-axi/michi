### Issues

#### Critical (Must Fix) — fixed, see below
**`DomainError::render()` silently dropped the `recovery` field.** The `.recovery(RecoveryHint)` builder stores `Option<RecoveryHint>`, but `render()` only called `append_hints`, never `append_recovery`. Any agent-facing error built with a recovery hint would render *without* it — the field existed on the struct but had zero effect on the actual stdout output, defeating its purpose. The crate's own `AgentResponse::render_text()` (`src/response.rs:103-110`) establishes the pattern (hints then recovery) that `DomainError::render()` should have mirrored. The existing `domain_error_carries_recovery` test only asserted the field was set (`e.recovery.as_ref().unwrap().tool == "get_issue"`), never called `.render()`, so nothing caught this.

I fixed it and committed as `d67442f` on top of `801bae2` (new commit, not amended):
```rust
crate::hints::append_hints(&mut out, &self.hints);
if let Some(r) = &self.recovery {
    crate::recovery::append_recovery(&mut out, std::slice::from_ref(r));
}
```
Added two regression tests: `domain_error_render_includes_recovery_block` (would have caught the bug) and `domain_error_render_with_no_hints_has_no_dangling_help_block` (closes the gap you flagged — confirms zero-hints output ends cleanly at `exit_code: 1\n` with no dangling `help[0]:`).
