### High

**1. `src/napi.rs:694-699` — Silent fallback to `"assistant"` for unrecognised `Audience` variants**

```rust
.map(|a| match a {
    michi_core::audience::Audience::Assistant => "assistant".to_string(),
    michi_core::audience::Audience::User      => "user".to_string(),
    _                                          => "assistant".to_string(), // ← problem
})
```

`Audience` is `#[non_exhaustive]`, so the wildcard arm is required when matching from the `michi` crate (external to `michi-core`). But the fallback is arbitrary and undocumented. If a future variant (`System`, `Tool`, etc.) is added, content for that surface is silently relabelled as `"assistant"` and delivered to the wrong MCP consumer. The audience field controls routing — a wrong value here is not cosmetic.

Fix: add a comment explaining why `"assistant"` is the conservative safe-default, and file a tracking note to revisit this arm whenever `Audience` grows. Alternatively, return an error for an unrecognised discriminant rather than silently coercing it.

### Medium

**2. `crates/michi-resilience/src/lib.rs:26-42` — `RetryConfigError` is not `#[non_exhaustive]`**

Every other public error type in the workspace carries `#[non_exhaustive]`: `ToonError`, `michi_core::Error`, `AlreadyDone`. `RetryConfigError` is a public enum callers can exhaustively match. Adding a fourth variant (`MaxRetriesIsZero`, `JitterMustBeFinite`, etc.) would be a breaking change. Add `#[non_exhaustive]`.

**6. `crates/michi-core/src/error.rs:26` — `Sensitive<T>` inner field is `pub`, defeating its purpose**


**8. Integer formatting inconsistency: `.to_string()` allocates where `write!` would not**

Several modules use `out.push_str(&n.to_string())` to append integers, allocating a temporary `String` per call. Other modules in the same codebase already import `use std::fmt::Write as _` and use `let _ = write!(out, "{n}")` instead. The inconsistency is clearest inside `render.rs`, which uses both styles in the same function:

- `crates/michi-toon/src/render.rs:155`: `out.push_str(&row_count.to_string())` — alloc
- `crates/michi-toon/src/render.rs:182`: `let _ = write!(out, "{n}")` — no alloc  
- `crates/michi-toon/src/render.rs:200`: `out.push_str(&total.to_string())` — alloc
- `crates/michi-toon/src/render.rs:210`: `out.push_str(&hints.len().to_string())` — alloc

Other affected files: `crates/michi-core/src/hints.rs:54`, `crates/michi-core/src/recovery.rs:55`, `crates/michi-core/src/idempotency.rs:57-106` (multiple calls), `crates/michi-resilience/src/lib.rs:308,310`. Add `use std::fmt::Write as _;` to those modules and convert to `write!`.

**9. `KvValue` serde-derived representation diverges from hand-rolled `render_json` output**

`KvValue::Float(f64, u8)` with `#[derive(serde::Serialize)]` serialises as a two-element tuple `[3.14, 6]`. `kv_value_to_json` at `crates/michi-core/src/kv/mod.rs:89` renders it as the bare number `3.140000`. `KvValue::Duration(Duration)` serde-serialises as a `{secs, nanos}` struct; `kv_value_to_json` at line 100 renders it as `"1.5s"`.

Callers using the `serde` feature for persistence or transport will get a schema that does not round-trip through the agent-facing JSON. Add a doc comment on `KvValue` clarifying that the serde representation and the `render_json` representation are intentionally different schemas, and that the latter is authoritative for agent consumption.
