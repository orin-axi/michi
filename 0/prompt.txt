## Two real bugs found (both inherited verbatim from the plan's own Step 3 reference code, confirmed by diffing against docs/superpowers/plans/2026-07-08-spec-parity.md:2763-2775 — not introduced independently by the implementer, but present in committed code)

**1. Missing per-row bounds check in `items()` — src/napi.rs:211-227.** The sibling free function `render_toon()` (napi.rs:109-113) checks `row.len() > MAX_FIELDS` for *every row*, in addition to `rows.len() > MAX_ROWS` and `fields.len() > MAX_FIELDS`. `JsAgentResponse::items()` only checks `rows.len()` and `fields.len()` — it never checks individual row length. A caller can send `rows: [[v1, ..., v10_000_000]]` (1 row, passes `rows.len() > MAX_ROWS`; header `fields` stays small) and the per-row conversion (`row.into_iter().map(js_value_to_rust).collect()`) does unbounded synchronous work before any check catches it. This is exactly the DoS class the module's own header doc claims to prevent (napi.rs:11-15: "a single crafted call from untrusted JS is otherwise able to force unbounded synchronous allocation"). Fix: add the same per-row check `render_toon()` has, before `self.take()`.

**2. `JsAgentResponse`'s entire impl (constructor + 9 methods) never uses `#[napi(catch_unwind)]`** — only bare `#[napi]`. This contradicts CLAUDE.md's non-negotiable ("NAPI: version = \"3\", `#[napi(catch_unwind)]` on every export") and this module's own header doc (napi.rs:10: "Every export uses `#[napi(catch_unwind)]` so a Rust panic cannot crash the host Node.js process"). I confirmed this isn't a technical limitation — checked napi-derive-backend 5.1.1 source (codegen/fn.rs:142-154, 282-316): `catch_unwind` codegen wraps the call generically regardless of FnKind (including `Constructor`), so it works fine on `&self`/`&mut self` impl methods. Currently any panic inside these methods (e.g. from a future change, or an unexpected invariant violation) would crash the whole Node process instead of throwing a catchable JS Error — silently defeating the stated purpose of every other export in this file. Fix: add `#[napi(catch_unwind)]` to all 10 items in the `JsAgentResponse` impl block (plus the constructor).
