## Part A — four deferred findings

**A1 — render_json() stringified recovery params (`src/response.rs`, `src/kv/mod.rs`)**
`render_json()` piped every `RecoveryHint` param through `recovery::kv_value_str()` (plain-text Cow<str>) then `json_string()`, so every value became a JSON string literal (`{"seconds":"30"}`, `{"force":"true"}`). Added two `pub(crate)` helpers in `src/kv/mod.rs` (chose this module over `recovery.rs` to avoid a module dependency cycle — `kv` sits below `recovery`/`response` in the dependency order, so both can call into it, but not vice versa):
- `json_escape_str(out, s)` — the RFC 8259 escaper, moved here from `response.rs` (which now just delegates `json_string()` to it, removing a second copy of the same escaping logic).
- `kv_value_to_json(out, &KvValue)` — `Int`/`Float`/`Bool` emit unquoted JSON literals, `Text` emits a quoted JSON string, `Missing` emits `null`, `Duration` emits a JSON string (`"4.2s"`, since JSON has no native duration type).

`render_json()`'s params loop now calls `kv::kv_value_to_json()` directly instead of going through `kv_value_str()`. New tests in both `response.rs` and `kv/mod.rs` confirm native JSON types render (`"seconds":30` not `"seconds":"30"`), including a `Missing` → `null` case.

**A2 — render_toon()/render_kv() were last-write-wins, not slot-specific (`src/response.rs`, `src/napi.rs`)**
Both were literal `self.render_text()` calls, so they followed `target` (whichever of `.items()`/`.kv_items()` was called last) instead of their own named slot — contradicting spec's literal "each render method reads only its own slot" text. Split the old `body()` into `toon_body()` (reads `items`/`fields`/`total_count` unconditionally) and `kv_body()` (reads `single_item`/`total_count` unconditionally), plus a shared `finish_text()` tail for hints/recovery. `render_toon()`/`render_kv()` now call their respective `_body()` directly, bypassing `target` entirely. `render(format)` is unchanged — it still dispatches on `target` for both `Text` and `Json`.

Replaced the two tautological tests (`render_toon_shorthand_matches_render_text_with_toon_format` etc. — true by construction for any implementation) with tests that populate both slots and assert `render_toon() != render_kv()`, plus that `render(format)` still follows last-write-wins. `JsAgentResponse::render_toon`/`render_kv` in `napi.rs` delegate straight to the Rust methods, so the fix propagated automatically — verified with new Rust-side NAPI tests and, since it was practical, a `node:test` case in `packages/michi-node/__test__/index.test.mjs` doing the same check through the actual compiled `.node` binary.

**A3 — NAPI setters aren't chainable (`docs/01-spec.md` only, no code change)**
Confirmed this was deliberate per Task 17's own design (Option+take() pattern, `napi::Result<()>` setters). Fixed the spec text instead of the code: rewrote the "builder boundary problem" section's prose and code example, and the `index.d.ts` `AgentResponse` class, to show `void`-returning setters and sequential-statement usage instead of `this`-chaining. Also folded this into the Q4 resolution (see Part B).

**A4 — recovery::kv_value_str() ignored Float precision (`src/recovery.rs`)**
The `Float(f, _decimals)` arm discarded the stored `u8` precision and used `f.to_string()`, while `kv::push_kv_value()` correctly respects it — same `KvValue::Float(x, 2)` rendered differently depending on whether it flowed through a `recovery[N]:` block vs a `kv`/`status` block. Fixed to `format!("{f:.*}", *decimals as usize)`, matching `push_kv_value()` exactly.
