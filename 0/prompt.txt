### All three recurring patterns confirmed

**1. Confounded witness** — two clean instances:
- **AC-011**: *both* `.retryable()` calls in the suite are no-ops on their chosen codes — `.retryable(false)` on `NotFound` (error.rs:417, already false) and `.retryable(true)` on `Unavailable` (error.rs:433, already true). Both assertions pass identically if `retryable()` were deleted entirely.

**2. Unbounded universal + safe witness** — AC-029/AC-031/AC-032/AC-033 each state a rule over a code family but are witnessed by exactly one code. AC-028's witness is genuinely discriminating (removing the `d.retryable` guard would fail it), but the interesting untested consequence is that a *User*-fault code explicitly marked `.retryable(true)` classifies as `Transient` and retryable — spec-consistent, empirically confirmed, zero coverage.
