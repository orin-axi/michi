### Important (Should Fix)

**1. `atty` 0.2 is unmaintained and has a known soundness advisory (RUSTSEC-2021-0145)**

`atty` calls `libc::isatty()` with a potentially invalid (negative) fd on Windows, which is undefined behavior. The crate has been abandoned since 2021. At MSRV 1.96, `std::io::IsTerminal` (stabilized in 1.70) is available with zero dependencies — `atty` is fully replaceable:

```toml
# Remove from Cargo.toml
atty = { version = "0.2", optional = true }

# Replace in cli feature with nothing — use std::io::IsTerminal directly
cli = ["dep:indicatif", "dep:inquire", "dep:crossterm", "dep:ctrlc", "pipeline"]
```

The plan spec includes `atty`, but this is a plan defect. `cargo deny` (Task 19) will flag this as a RUSTSEC advisory and fail CI.

**2. `michi-node/Cargo.toml` missing `publish = false`**

The placeholder has no publish guard. `cargo publish -p michi-node` (or an accidental workspace publish) would attempt to publish an empty stub. This needs a safety guard now, before anyone runs publish commands:

```toml
# packages/michi-node/Cargo.toml
[package]
name    = "michi-node"
version = "0.1.0"
publish = false            # ← add this
edition.workspace = true
```

**3. `napi-build` optional build-dep in root is unreachable**

`napi-build = { version = "2", optional = true }` sits in the root `[build-dependencies]`, but the `napi` feature only activates `dep:napi` and `dep:napi-derive` — it does **not** include `dep:napi-build`. This means `napi-build` has no activation path from any feature and will never be compiled. Additionally, `build.rs` is `fn main() {}`, so even if activated it would do nothing. The plan correctly notes that `napi-build` belongs in `packages/michi-node/build.rs` (Task 17). The root entry is dead weight that will confuse future maintainers. Remove it from the root Cargo.toml and add it in Task 17.

### Minor (Nice to Have)

**4. `rust-toolchain.toml` doesn't pin a channel version**

`channel = "stable"` floats to the current stable. The MSRV is 1.96 but the toolchain could be 1.99 or 2.0 on a different machine. Low risk (the `rust-version` guard catches genuine incompatibilities) but a pinned channel like `channel = "1.96"` or a specific recent stable gives reproducible CI toolchain installs. Per-spec but worth revisiting.

**5. `michi-node/Cargo.toml` doesn't inherit workspace metadata**

The placeholder omits `rust-version.workspace`, `license.workspace`, `repository.workspace`, `authors.workspace`. These are free to add now and prevent inconsistent metadata if someone runs `cargo metadata`. They'll be needed in Task 17 anyway.

**6. CLAUDE.md omits `telemetry` from the module guide**

The plan's file map (line 70) includes `src/telemetry/mod.rs` as a Task 14 target, but the module guide table in CLAUDE.md stops at `pipeline`. A future agent implementing Task 14 won't see `telemetry` in the guide.

**7. `.typos.toml` lost the instructional comment**

The plan's spec included `# Add known false-positives here` inside `extend-ignore-identifiers-re`. The empty array without comment is fine functionally but loses the intent for the first contributor who adds a false positive.
